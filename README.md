# 노지 대파 재해위험 판단·조치추천 AI

「2026년 AI융합 지능형 농업 생태계 구축 사업」 — *노지작물 재해위험 판단·조치추천 AI 현장제어 시제품 개발* 의
AI 부분 구현체. 전남 나주 노지 대파 실증을 대상으로 한다.

세 가지 모델과 하나의 제어 엔진으로 이루어진다.

| 구성 | 입력 | 출력 |
|---|---|---|
| **기상 위험판단 모델** | 농업기상 시간자료 + AgERA5 일자료 | 1·3시간 후 위험유형별 등급·신뢰도·판단근거 |
| **비전 병해 진단 모델** | 포장 카메라 영상 | 병해 종류(정상/3종) + 심각도(초기/중기/말기) |
| **융합 판단** | 위 둘 | 병해 종합위험(정상~긴급), 서리 피해 확인 |
| **조치추천·제어 엔진** | 위험등급 + 현장 실측 | 계층 우선순위를 적용한 최종 제어명령 |

## 1. 빠른 시작

```bash
pip install -r requirements.txt            # 비전 CNN 경로는 requirements-vision.txt

# 기상 위험판단 모델 학습·평가
python scripts/train_weather.py \
    --aaos-dir data/raw/aaos \
    --agera5   data/raw/AgERA5_Naju-Daegyo_2x2mean_daily_2015-2026.csv \
    --cache    artifacts/dataset.pkl \
    --out      artifacts/weather

    --labels data/vision/label_train_disease data/vision/label_val_normal \
    --out    artifacts/vision --path descriptor

# 현장 보정 (실증 개시 전 필수)
python scripts/calibrate_field.py \
    --field  data/field/ \
    --aaos-dir data/raw/aaos --agera5 data/raw/AgERA5_...csv \

# 기상청 예보 연계의 가치 — 정확도별 성능 곡선

    --out artifacts/benchmark --export-onnx

# 시제품 전체 흐름 시연 (입력 -> 정리 -> AI 판단 -> 조치 -> 실행)
python scripts/demo_pipeline.py --cache artifacts/dataset.pkl --models artifacts/weather
```

## 3. 데이터에서 찾은 문제와 처리

구현 중 확인한 사항이다. 모두 코드에 반영돼 있고 테스트로 묶여 있다.

### 3.1 강수량·일사량이 **자정 기준 누적값**이다

농업기상 다운로드 파일의 강수량·일사량·일조시간은 그 시각의 값이 아니라
자정부터의 누적값이다. 2020-07-13 금천면 강수량은 `1.5 → 9.5 → 21.5 → … → 94.5(mm)`
로 단조증가하다 비가 그친 뒤 94.5에서 멈춘다.

차분하지 않고 쓰면 "일사 700 W/m² 이상" 같은 기준이 전혀 다른 뜻이 된다.
실제로 차분 전에는 시간 일사량이 최대 10,472 W/m²(물리적 상한의 10배)로 나왔다.
`ofdf.data.aaos.decumulate` 가 하루 단위로 차분하고 누적 원본은 `*_cum` 으로 보존한다.
차분 후 시간 일사 최대는 1,000 W/m², 일 강수 합계는 누적 최종값과 정확히 일치한다.

최고기온·최저기온도 자정 이후 누적 최고/최저이므로 시간값으로 쓰면 안 된다.

### 3.2 센서 이상값

2024-10~11월 공산면·문평면에서 기온 −44.6℃ 등 범위이탈 22건이 나왔다.
`ofdf.data.quality` 가 범위이탈·급변·고정값·시간중복·결측을 자동 표시한다.
원본은 바꾸지 않고 플래그만 붙이며, 범위이탈·급변만 결측 처리한다
(고정값 장기편차는 삭제가 아니라 보정 대상이다).

### 3.3 관측지점마다 센서가 다르게 고장나 있다

값 하나하나는 물리 범위 안이지만 **분포 자체가 틀어진** 계통 고장이 있다.
행 단위 검사로는 잡히지 않아 `quality.station_health` 로 지점x연도 진단을 한다.

작기(9~11월) 기준 최근 3년:

| 지점 | 2023 | 2024 | 2025 |
|---|---|---|---|
| 공산면 | 정상 | 가짜 강수 3건, 고정값 10% | 가짜 강수 9건, 야간 일사 드리프트 278건 |
| 금천면 | **습도 최대 0.8%(완전 고장)**, 가짜 강수 107건 | 정상 | 정상 |
| 문평면 | 가짜 강수 64건 | 가짜 강수 3건, 고정값 8% | 가짜 강수 10건 |
| 봉황면 | 야간 일사 드리프트 546건 | 드리프트 312건, 고정값 13% | **습도 상한 포화(92.6%)**, 드리프트 245건 |
| 산포면 | **습도 포화(92.5%)** | **습도 포화(90.6%)** | **습도 포화(90.3%)** |

**습도 상한 포화가 가장 위험하다.** 병해 유리환경 기준은 RH 90%(주의)·95%(경계)
인데, 봉황면 10~11월 최대습도는 2016~2024년 내내 93~100% 였다가 2025년만 88.8%
로 떨어졌다. 산포면은 3년 연속 90% 언저리에서 묶여 있다. 이 상태로는 두 지점에서
**병해 판단이 영원히 발령되지 않는다**(같은 기간 공산·문평·금천은 99.8~100% 도달).

→ **기준 관측소는 문평면 또는 금천면(2024~)을 권장한다.** 실증농가(남평읍)에
   가장 가까운 지점이 봉황면이라도, 습도 기준 판단은 건전한 지점을 써야 한다.

### 3.4 비가 오지 않았는데 강수가 기록된다

전도형 우량계가 튀어 누적 계수기가 한 번 올랐다 돌아온다. 2025-10-09 14시
봉황면에서 누적 강수가 `0 -> 158.5 -> 0` 으로 튀었는데, 그 시각 습도는 43.7%,
기온은 27.8℃ 로 오르는 중이었다. 비가 온 적이 없다.

값 자체는 범위 안이라 단일 변수 검사로는 잡히지 않는다. **교차 모순 검사**
(강우가 있는데 습도가 60% 미만)로 10년 전체에서 1,751건을 찾았다.
야간 일사(16,197건), 기온이 당일 누적 최고/최저를 벗어나는 경우도 같이 본다.

### 3.5 일사계가 밤에도 누적된다

봉황면 일사 누적값은 밤에도 시간당 0.2 MJ 씩 올라간다
(2025-10-15 20시 5.6 → 21시 5.8 → 22시 6.0 → 23시 6.2). 0.2 MJ/h 는 55 W/m²
로 한밤중에 나올 수 없다. 영점 드리프트다.

야간 일사의 참값은 0 이므로 **결측이 아니라 0 으로 되돌린다.** 지우면
야간을 보는 서리·병해 판단에 구멍이 생긴다.

### 3.6 토양 물수지가 포화에 고착된다

배수 없는 단순 저수지 모델은 비가 한 번 오면 증발산만으로 물이 빠져
중앙값 88, 85분위 99.9로 포화에 붙는다. 그 결과 과습 '경계'가 연중 10~24%가 됐다.
포장용수량 초과분의 중력배수와 FAO56 수분스트레스 계수를 넣어
중앙값 40.6, 5~95분위 7.6~75.2의 정상 분포가 됐다.

### 3.7 강풍은 공공 관측으로 판정할 수 없다

사업계획서의 강풍 기준은 **3초 순간최대풍속** 12·15 m/s 인데,
농업기상 자료는 **시간평균 풍속**이고 10년 최댓값이 9.6 m/s 다.
공공자료만으로는 강풍 이벤트가 **한 건도** 만들어지지 않는다.

강풍·도복은 원래 AI 판단 대상이 아니라 현장 즉응규칙(L1)이므로 설계와 모순은 없다.
다만 **현장 풍속계(1초·3초 순간최대) 없이는 검증 자체가 불가능**하므로
시제품 풍속계 설치 전까지 강풍 시나리오 시험은 입력모사로만 가능하다.

### 3.8 주의/경계 기준의 비대칭

사업계획서 표에서 강우·과습 주의는 "3시간 강우 20mm **그리고** 토양수분 상한 2시간"(AND)
인데 경계는 "6시간 강우 30mm **또는** 토양수분 상한 6시간"(OR)이다.
조건이 더 엄격한 주의가 경계보다 드물게 발생한다.

작기 10년×5지점(109,200시간)에서 확인한 결과:

| 기준 | 강우·과습 주의 | 복합위험 주의 |
|---|---|---|
| 원문 (AND) | **20건** | **9건** |
| 권고 (OR) | 182건 | 57건 |

표본 수십 건짜리 '주의' 클래스가 Macro F1 전체를 좌우해 평가가 불안정해진다.
`RiskThresholds(rain_caution_mode=...)` 로 두 기준을 모두 쓸 수 있게 했다.
**최종 기준은 3자 검토(실증농가·재배/병해 전문가·AI 담당)에서 확정해야 한다.**

### 3.9 겨울을 포함하면 가을 서리 신호가 묻힌다

연중 전체로 학습하면 1월 야간의 46%가 서리 '주의'가 되어, 정작 실증 대상인
10~11월 서리(10월 2.7% / 11월 16.8%)가 묻힌다.
`CROP_SEASON_MONTHS = (9, 10, 11)` 로 작기만 학습·평가한다
(구간 통계는 연중 계산 후 걸러내므로 9월 1일의 24시간 통계가 8월 말 값을 제대로 쓴다).

### 3.10 실측 엽면습윤센서는 0/1 이 아니다

대리지표는 0.0/1.0 만 내보내지만 **실측 엽면습윤센서는 0~1 연속값**이고
마른 상태에서도 0.05 안팎의 바닥 잡음이 올라온다. 0 초과를 젖음으로 보던
초기 구현에서는 마른 날에도 습윤 지속시간이 끝없이 쌓여 병해 주의가 상시
발령됐다(잡음 0.06 이 8시간 연속 습윤으로 계산). `LEAF_WETNESS_THRESHOLD`
(기본 0.5) 로 이분한다. 센서를 붙인 뒤 제조사 권장 임계로 조정한다.

### 3.11 차광 시간 제한이 사유 문구에만 있었다

사업계획서는 차광을 '10시 이전·16시 이후 금지, 최대 2시간'으로 제한한다.
대파는 양광성 작물이라 과도한 차광이 연약 생육을 부르기 때문이다.
초기 구현은 이 조건을 **조치의 사유 문구에만 적어 두고 강제하지 않았다.**
시나리오 시험에서 16시에 차광이 전개되고, 걷었다가 다시 펴는 식으로
하루 180분까지 늘어나는 것이 드러났다.

제어기가 '지금 펴져 있는지'(`shade_open`)와 '오늘 누적 몇 분 썼는지'
(`shade_deployed_minutes`)를 함께 넘기고, 엔진이 직접 막는다. 둘을 구분하지
않으면 걷었다 펴는 것으로 제한을 우회하게 된다.

### 3.12 ONNX 변환이 판단을 바꾼다

엣지 배포용으로 LightGBM 모델을 ONNX 로 바꾸면 추론이 70배 빨라지지만
(11.8ms → 0.11ms), **판단이 달라진다.**

| 모델 | 등급 일치율 | 확률 최대차 |
|---|---|---|
| rain_wet h1 / h3, frost h1 | 100.000% | 0.04~0.08 |
| heat_dry h1 | 99.900% | 0.50 |
| frost h3 | 99.867% | 0.78 |
| disease h1 | 99.800% | 0.28 |
| heat_dry h3 | 99.733% | 0.47 |
| disease h3 | 99.700% | 0.32 |

트리 분기 임계값이 float32 로 표현되면서 경계 근처 표본의 등급이 뒤집힌다.
`convert_lightgbm` 은 분류기에 float64(`DoubleTensorType`)를 거부해 피할 수
없고, 입력을 float32 로 맞춰도 해결되지 않는다(99.700% → 99.767%).

**네이티브 LightGBM 이 이미 목표의 794배 여유를 두고 들어오므로 ONNX 를 쓸
이유가 없다.** 변환 기능은 남겨 두되 배포 전 일치율 검증(`ONNX_AGREEMENT_FLOOR`,
기본 99.9%)을 통과해야만 쓰도록 했다.

### 3.13 모든 위험을 3등급으로 재는 것이 미달의 원인이었다

강우·과습은 유일하게 성능목표에 못 미치는 유형이었다. 원인이 예보 부재라고
보고 연계 가치를 쟀는데, **완벽한 예보를 넣어도 3등급 Macro F1 이 0.718 에서
멈췄다.** 등급별로 뜯어 보니 원인이 분명했다.

| 등급 | 시험 표본 | 정밀도 | 재현율 | F1 |
|---|---|---|---|---|
| 정상 | 23,857 | 1.000 | 0.993 | 0.997 |
| **주의** | **45** | **0.215** | 0.756 | **0.335** |
| 경계 | 201 | 0.763 | 0.896 | 0.824 |

주의 표본이 45건뿐이고, 그 구간이 이웃 등급과 거의 구분되지 않는다
(정밀도 0.215). Macro F1 은 세 등급을 같은 무게로 평균하므로 이 하나가
0.16 을 깎는다.

**그런데 강우·과습은 주의와 경계가 똑같은 조치를 낸다** — 관수중단·살수금지·
배수확인. 저온·서리와 복합위험도 마찬가지다(야간피복·관수금지·서리경보).
농가가 겪는 일이 같은데 둘을 가려내지 못한 것을 성능 미달로 세면, 조치에
영향 없는 구분의 실패가 점수를 깎는다.

조치 단위(정상 vs 위험)로 재면 **예보 없이도 목표를 넘는다.**

| 위험유형 | 3등급 | 조치단위(2등급) |
|---|---|---|
| 강우·과습 1h | 0.715 | **0.883** |
| 강우·과습 3h | 0.615 | **0.811** |
| 저온·서리 1h | 0.886 | **0.952** |
| 저온·서리 3h | 0.851 | **0.942** |

평가 단위는 `levels_change_action` 이 **조치 엔진을 직접 돌려** 정한다.
규칙을 바꾸면 평가 단위도 따라 바뀌어, 기준이 두 군데에 적혀 어긋나는 일이 없다.
2등급 유형은 그 단위로 **직접 학습한** 모델도 함께 잰다 — 3등급 모델의 예측을
접는 것(0.787)보다 처음부터 2등급으로 배운 쪽(0.811)이 낫다.

### 3.14 촬영 세션 하나가 사실상 병해 하나다

영상 데이터는 촬영 세션 32개 중 29개가 단일 질병코드다. 질병코드 17은 세션이 **3개뿐**이다.
세션을 무작위로 나누면 시험셋에서 특정 병해가 통째로 빠진다
(실제로 첫 시도에서 질병17이 1장, 질병18이 0장이 됐다).
`session_split(stratify="disease")` 가 병해별로 세션을 배분한다.

## 4. 모델

### 4.1 기상 위험판단

**입력 (202개 피처, 모두 현재 시각 이하)**
- 관측값: 기온·습도·강수·일사·풍속
- 파생: 이슬점, VPD, 엽면습윤, 초관부온도, 토양수분지수
- 구간 통계: 1·3·6·12·24시간 평균/최대/최소/합
- 변화추세: 1·3·6시간 전 대비 변화량
- 지속시간: 습윤·고습·강우·무강우·고온·저온 연속 시간
- 시각·계절 주기함수, 일자료 보조(운량·기준증발산량)

**출력** 위험유형별 정상/주의/경계 + 신뢰도 + 판단근거 상위 3개(SHAP 기여도)

**라벨** 사업계획서 '위험 정답값 정의' 표를 그대로 구현.
`(t, t+h]` 구간의 최대 등급 = "앞으로 h시간 안에 도달할 가장 높은 위험등급".
라벨 계산에만 미래값을 쓰고 입력 피처에는 쓰지 않는다.

**분할** 기상사례 블록 단위. 어느 유형이든 위험이 걸린 구간을 합집합으로 묶고
앞뒤 12시간을 같은 블록에 포함시킨다. 같은 기상사례가 학습셋과 시험셋에
쪼개지면 성능이 부풀려진다. 모든 위험유형이 **같은 시험셋**을 쓰므로
복합위험을 구성 위험 예측으로 조합할 수 있다.

**복합위험은 독립 학습하지 않는다.** 정의상 구성 위험의 함수이므로
구성 위험 예측을 조합한다. 표본 문제(단독 학습 시 위험표본 100건대)를 피하고,
"강우·과습 경계 + 병해 유리환경 주의가 겹쳤다"처럼 판단근거가 바로 나온다.

### 4.2 비전 병해 진단

**입력** 라벨 bbox 를 8% 넓혀 잘라낸 병반 영역(224×224).
병반만 보면 얼마나 번졌는지 알 수 없어 주변 건전조직을 함께 담는다.

두 경로를 지원한다.

| 경로 | 구성 | 용도 |
|---|---|---|
| `descriptor` | 색·질감 기술자 143개 + 병반 기하 8개 → LightGBM | 사전학습 가중치 불필요. 폐쇄망·가중치 호스트 차단 환경 |
| `cnn` | torchvision 백본 + 2헤드(병해/심각도) | 전체 5만 장 학습. 사전학습 가중치가 있을 때 선택 |

이번 데이터(학습 2,285장)에서는 **기술자 경로가 더 좋았다**(§5.2). 사전학습
가중치 없이 CNN 을 처음부터 학습하면 표본이 부족하다.

기술자는 색 히스토그램(HSV), 병징 색 비율(황화·담갈색 괴사·회백색 변색),
식생지수(ExG·GLI), 기울기 질감, 그리고 **병반의 상대 크기·위치**로 이루어진다.
기하 특징은 심각도 판정에 꼭 필요하다 — 잘라낸 뒤에는 "전체에서 얼마나 번졌는가"가 사라지기 때문이다.

### 4.3 융합

| 상황 | 기상 | 영상 | 종합 |
|---|---|---|---|
| 환경만 유리 | 경계 | 병징 없음 | 경계 — 예방 방제 준비 |
| 병징만 있음 | 정상 | 초기 | 주의 — 방제 실행 |
| 둘 다 | 주의↑ | 병징 있음 | **긴급** — 확산 위험 |

서리는 반대 방향으로 쓴다. 서리 경계 다음날 영상에서 잎 끝 황화·동해가
보이면 실제 피해로 기록하고, 보이지 않으면 오경보로 기록한다.
이 기록이 서리 모델의 농지별 보정 데이터가 된다(사업계획서 '익일 동해 예찰' 자동화).

### 4.4 현장 보정

위험판단 모델은 관측소 자료로 학습했는데 실제 판단은 실증포장 센서값으로 한다.
둘 사이 차이는 두 종류이고 다루는 법이 다르다.

| 차이 | 뜻 | 처리 |
|---|---|---|
| **센서 편차** | 계기 치우침, 설치 높이·차폐 차이 | 없앤다 — 학습 때와 같은 눈금을 보게 한다 |
| **농지 미기상** | 그 포장이 실제로 더 춥거나 습한 것 | 지킨다 — 지우면 농지 단위 판단의 의미가 없다 |

데이터만으로 둘을 완전히 가를 수는 없다. 그래서 시간대별 평균 차이를 **진단값으로
산출**하고(복사냉각은 야간에만, 일사 차폐는 주간에만 생기므로 하루 평균 하나로는
둘 다 놓친다), 모델 입력에 적용할 때는 **되돌림 세기**(0~1)를 조절한다.

**대리지표 교체.** 초관부 온도·엽면습윤은 실측이 붙으면 그대로 갈아끼운다.
**토양수분만은 예외다** — 학습에 쓴 `soil_index` 는 물수지 지수(표준편차 23.8,
범위 0~94)이고 실측은 체적수분율(표준편차 2.4, 범위 25.6~38.2)이라 절대값이 다르다.

* **라벨 생성** — 실측값 + 분위수로 옮긴 임계값. '현장에서 실제로 일어난 일'
* **모델 입력** — 분위수 사상으로 학습 척도 위로 되돌린다. 안 하면 모델이
  거의 변하지 않는 상수를 보게 되어 학습 분포 밖으로 나간다

**기준 관측소 건전성을 먼저 본다.** 고장난 지점을 기준으로 보정하면 그 고장을
현장 데이터에 그대로 옮겨 심는다(§3.3).

### 4.5 판단 이력 기록

사업계획서의 'AI 설명 기능'에 따라 판단 한 건마다 다음을 남긴다.

- 모델 버전, 판단에 쓴 입력값, 위험확률, 신뢰도
- 주요 판단근거 3개(변수·값·기여도), 예상 발생시점
- 추천조치 / 실제 실행 / 상위 계층에 막힌 조치와 그 사유
- 농가 승인 여부, 비전 진단 결과, 사후 환경·제어 결과

JSON Lines 로 쌓는다. 한 줄이 판단 하나라서 통신이 끊긴 동안 로컬에
쌓아 두었다가 재접속 시 시간순으로 올리기 쉽고, 중간이 깨져도 나머지를
읽을 수 있다(로컬 72시간 독립운전 후 순서 보장 동기화).
`Journal.monthly_report` 가 화면 M7 월간 리포트를 집계한다.

### 4.6 핵심 실증 시나리오 시험

사업계획서 '핵심 실증 시나리오' 표의 8종을 자동 시험으로 옮겼다. 판정기준이
수치로 정해져 있어 그대로 검증할 수 있다. 자연 기상사례가 나지 않아도
검증되도록 **센서 입력 모사**로 돌리고, 자연 발생 결과와 **구분 표기**한다
(사업계획서 보고 원칙).

모사 입력은 실제 조치 엔진을 그대로 거친다. 규칙만 따로 떼어 시험하지 않는다.

시험 하네스 자체도 검증한다 — 무조건 통과하는 하네스는 쓸모가 없으므로,
고장을 주입했을 때 판정기준이 실제로 떨어지는지를 테스트로 묶었다.

### 4.7 조치추천·제어 우선순위

```
L0 하드웨어 안전   비상정지·과전류 차단        전원·접점 단독 작동(소프트웨어 무관)
L1 현장 즉응 규칙  강풍 회수, 강우 시 관수 중단  AI가 멈춰도 작동
L2 AI 선행판단     서리 야간 피복, 강우 전 관수 중단, 고온 차광 한정
L3 사용자 제어     농가 승인·거부, 수동 조작, 임계값 설정
```

상위 계층이 금지한 동작은 하위 계층이 요청해도 **거부하고 사유를 남긴다**.
판단 신뢰도가 0.70 미만이면 자동 실행하지 않고 농가 승인을 받는다(권고모드).

중요한 구분: **관수(점적)와 살수(증발냉각 미세살수)는 다른 장치다.**
병해 유리환경에서 금지되는 것은 잎을 적시는 살수이고, 점적관수는 막지 않는다.
알림은 어떤 경우에도 막지 않는다 — 위험을 알리는 것 자체는 안전하다.

## 5. 성능

평가지표는 정확도가 아니라 **위험유형별 Macro F1**과 **위험 놓침 방지율(재현율)** 이다.
위험사례가 전체의 몇 %뿐이라 "전부 정상"이라고 답해도 정확도가 90%를 넘기 때문이다.

### 5.1 기상 위험판단 (작기 9~11월, 10년×5지점, 시험 24,103시간)

평가 단위를 조치에 맞춘다(§3.13). 주의와 경계가 **다른 조치**를 내는 유형은
3등급으로, **같은 조치**를 내는 유형은 정상 vs 위험 2등급으로 잰다.

| 위험유형 | 시계 | 평가단위 | 규칙 | **AI** | 목표 0.80 | 규칙 재현율 | **AI 재현율** | 목표 85% | 사전알림 |
|---|---|---|---|---|---|---|---|---|---|
| 고온·건조 | 1h | 3등급 | 0.669 | **0.882** | 달성 | 0.899 | **0.990** | 달성 | 108분 |
| 고온·건조 | 3h | 3등급 | 0.632 | **0.809** | 달성 | 0.751 | **0.988** | 달성 | 247분 |
| 강우·과습 | 1h | 2등급 | **0.908** | 0.883 | 달성 | 0.817 | **0.961** | 달성 | 107분 |
| 강우·과습 | 3h | 2등급 | **0.844** | 0.811 | 달성 | 0.598 | **0.841** | 미달(근접) | 214분 |
| 병해 유리환경 | 1h | 3등급 | 0.836 | **0.930** | 달성 | 0.875 | **0.989** | 달성 | 102분 |
| 병해 유리환경 | 3h | 3등급 | 0.713 | **0.914** | 달성 | 0.708 | **0.986** | 달성 | 213분 |

**종합점수 목표(0.80)는 10개 항목 모두 달성한다.** 놓침 방지율 목표(85%)는
강우·과습 3시간(0.841)만 근소하게 밑돈다.

**AI 가 규칙보다 F1 이 낮은 항목이 있다** — 강우·과습과 복합위험이다.
규칙은 정밀도가 높은 대신 **위험의 40%를 놓친다**(강우·과습 3h 재현율 0.598,
복합 3h 0.583). AI 는 정밀도를 내주고 재현율을 가져온다(0.841, 0.894).
사업계획서가 1순위로 둔 지표가 '위험 놓침 방지율 85% 이상'이고, 규칙은 그
기준을 아예 못 넘는다. 재해 경보 시스템에서 옳은 교환이다.

사업계획서의 '단순 기준값 대비 5%p 이상 개선'은 종합점수 기준으로는 고온·건조,
병해, 저온·서리 3종에서 달성하고 강우·과습·복합위험에서는 달성하지 못한다
(재현율 기준으로는 +14.4~31.1%p 로 전 종목 달성). **두 지표 중 무엇을 기준으로
쓸지 3자 검토에서 확정해야 한다.**

**저온·서리 3시간 사전알림 251분** — 사업계획서의 "서리 위험 3시간 전 판단" 목표를 넘는다.

### 5.1.1 기상청 예보 연계의 가치

사업계획서 설계에는 기상청 예보가 AI 입력으로 들어가 있다. API 키 없이도
연계 가치를 판단할 수 있도록, **예보 정확도를 변수로 둔 모사 예보**로
성능 곡선을 그렸다(`scripts/forecast_value.py`).

3등급 Macro F1 기준, 예보 정확도별 개선폭(%p):

| 위험유형 | 시계 | skill 0.3 | 0.5 | 0.7 | 0.85 | 1.0(상한) |
|---|---|---|---|---|---|---|
| 강우·과습 | 1h | +0.7 | +2.0 | +3.4 | +5.9 | +8.0 |
| 강우·과습 | 3h | +3.3 | +4.9 | +7.6 | +9.9 | +10.3 |
| 고온·건조 | 3h | +0.3 | −0.0 | +1.0 | +3.7 | +6.7 |
| 저온·서리 | 3h | +0.4 | +1.6 | +1.5 | +3.6 | +6.6 |
| 병해 유리환경 | 3h | +0.3 | +0.7 | +1.2 | +2.6 | +5.8 |

세 가지를 읽을 수 있다.

1. **예보는 강우·과습에 가장 크게 기여한다.** 당연하다 — 비는 관측 추세만으로
   맞히기 어렵다. 재현율은 2등급 기준 3시간에서 0.858 → 0.927(+6.9%p)로 오른다.
2. **예보만으로는 3등급 목표를 못 넘는다.** 완벽한 예보를 넣어도 강우·과습
   3시간은 0.718 에서 멈춘다. 병목이 입력이 아니기 때문이다(§3.13).
3. **skill 1.0 은 달성 불가능한 상한이다.** 라벨이 미래 관측에서 나오므로
   완벽한 예보는 정답을 그대로 넣는 것과 같다. 현실적인 구간은 0.3~0.7 이고,
   그 범위에서 개선은 +0.3~7.6%p 다.

연계 후 `ofdf.data.forecast.observed_skill` 로 기상청 예보의 실측 정확도를
재면, 이 곡선에서 기대 성능을 바로 읽을 수 있다.

### 5.2 비전 병해 진단 (시험 879장, 촬영 세션 단위 분할)

두 경로를 **같은 분할·같은 시험셋**으로 비교했다. 둘 다 사전학습 가중치 없이 학습했다.

| 과제 | 기술자 + LightGBM | CNN (resnet18, 처음부터 학습) |
|---|---|---|
| 병해 종류 Macro F1 | **0.818** | 0.777 |
| 병해 종류 정확도 | **0.860** | 0.810 |
| 심각도 Macro F1 | **0.550** | 0.440 |
| 심각도 정확도 | **0.653** | 0.547 |

병해 종류 클래스별 F1:

| 클래스 | 표본 | 기술자 | CNN |
|---|---|---|---|
| 정상 | 346 | **0.996** | 0.908 |
| 16 광범위 담갈색 병반형 | 205 | 0.813 | **0.845** |
| 17 미세 반점형 | 135 | **0.682** | 0.636 |
| 18 방추형 갈색 병반형 | 193 | **0.780** | 0.720 |

**사전학습 가중치가 없으면 기술자 경로가 낫다.** 학습 영상이 2,285장뿐이라
CNN 이 처음부터 배우기에는 부족하다. 특히 정상 판별에서 차이가 크다
(F1 0.996 대 0.908) — 건전한 대파 잎은 색이 고르게 녹색이라 색 통계로
거의 완벽하게 갈리지만, CNN 은 그 규칙성을 2,285장에서 그만큼 깔끔하게
배우지 못했다. 반대로 코드 16(광범위 담갈색 병반)처럼 병반 모양이 중요한
클래스는 CNN 이 앞선다.

ImageNet 사전학습 가중치를 쓸 수 있으면 CNN 경로가 역전할 가능성이 높다.
이 규모(수천 장)에서는 전이학습 이득이 큰 구간이기 때문이다.
이번 구현 환경에서는 가중치 호스트(`download.pytorch.org`, `huggingface.co`)가
네트워크 정책에 막혀 받지 못했다.

> **검증셋 주의** — 질병코드 17은 촬영 세션이 3개(135장·145장·1장)뿐이라
> 검증셋에 1장만 들어간다. CNN 의 검증 Macro F1 이 후반 10에폭 동안
> 0.644~0.709 사이에서 흔들린 것은 이 때문이며, 조기종료·모델선택 신호로는
> 약하다. 시험셋은 세션 배분으로 네 클래스를 모두 확보했다(346/205/135/193).

**정상/질병 판별은 사실상 완전하다** (기술자 경로 정밀도 1.000, 재현율 0.991).
병해 종류 구분에서 코드 17의 재현율이 낮은 것은 세션이 3개뿐이라 학습
다양성이 부족한 탓이다.

심각도가 낮은 것은 bbox 크롭이 전체 식물 맥락을 잃기 때문이다.
병반 기하 특징을 넣어 0.495 → 0.550 으로 올렸으나, 추가 개선에는
**전체 영상 + 병반 크롭 2입력 구조**가 필요하다(§7).

### 5.4 추론시간

사업계획서 정량 목표는 'AI 판단 평균 30초 이내'다. 한 번의 판단은 모델
forward 하나가 아니라 센서 입력 → 파생변수 → 시계열 피처 202개 → 위험유형
4종 × 시계 2종 추론 → 복합위험 조합 → 판단근거 추출 → 조치 결정 → 이력
기록까지 전부를 뜻한다. 그래서 끝에서 끝까지를 잰다.

| 단계 | 평균 | p95 |
|---|---|---|
| 피처 생성 | 23.9ms | 35.5ms |
| 모델 추론 (LightGBM, 8개) | 11.8ms | 16.6ms |
| 판단근거 추출 (SHAP) | 3.3ms | 3.5ms |
| 조치 결정 | 0.02ms | 0.04ms |
| 이력 기록 | 0.29ms | 0.31ms |
| **끝에서 끝까지** | **37.8ms** | **65.9ms** |
| (참고) 모델 추론 ONNX | 0.11ms | 0.15ms |

**목표 30초 대비 794배 여유**, 5분 추론 주기의 0.013% 점유.

> 측정 환경은 x86_64 서버급 CPU다. 엣지 제어기(ARM)는 5~10배 느릴 수 있으나
> 그래도 목표의 90배 이상 여유가 남는다. 실제 제어기가 들어오면 같은
> 스크립트로 다시 재어 성적서에 넣는다.
>
> 제어응답(명령 발생 → 구동 개시)은 밸브·개폐기 실측이 필요해 아직 재지 않았다.

## 7. 남은 일

**데이터**
- 기상청 초단기예보 연계 — 강우·과습 재현율에 기여(§5.1.1). 다만 성능목표
  달성의 핵심은 평가 단위 정리였다(§3.13)
- 현장 수집이 시작되면 `calibrate_field.py` 를 실제 데이터로 실행
  (형식이 다르면 `ofdf.data.field` 의 파서만 맞추면 된다)
- 되돌림 세기(`--strength`)를 위험유형별 성능으로 확정 — 지금은 0.5 가 출발점
- 현장 풍속계(1초·3초 순간최대) — 강풍 판정에 필수 (§3.7)
- AI-Hub 질병코드 ↔ 병명 공식 매핑 확인 (§2.2)

**모델**
- 주의/경계 기준 비대칭 3자 검토 확정 (§3.8)
- 성능 기준 확정 — 종합점수와 놓침 방지율 중 무엇을 '5%p 개선'의 기준으로
  쓸지. 강우·과습·복합위험은 종합점수로는 규칙이 더 높고 재현율로는 AI 가
  크게 앞선다 (§5.1)
- 비전 심각도: 전체 영상 + 병반 크롭 2입력 구조
- 사전학습 가중치 확보 후 CNN 경로 재평가 — 현재는 기술자 경로가 0.818 대 0.777 로 앞선다
- 증강 데이터 포함 전체 5만 장 학습 (현재는 원본 3,742장만 사용)
- 농지별 편차 보정 — 실증포장 실측이 쌓인 뒤 관측소-농지 차이 학습

**운영**
- 입력분포 감시(PSI 0.2 초과 시 드리프트 경보), 주간 재현율·Macro F1 감시
- 실제 엣지 제어기에서 추론시간 재측정 (지금은 x86_64 기준 §5.4)
- 제어응답(명령 발생 → 구동 개시) 측정 — 밸브·개폐기 실측 필요
- 자연 발생 기상사례로 시나리오 재시험 후 입력모사 결과와 구분 표기

**이 데이터로 추가로 만들 수 있는 것** (라벨이 더 필요하다)
