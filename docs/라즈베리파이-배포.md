# 라즈베리파이 엣지 제어기 배포

현장 제어함 안의 엣지 제어기로 라즈베리파이를 쓸 때의 설치·운영 기준이다.

## 자원 소요 — 실측

판단 1회는 모델 추론 하나가 아니다. 센서 입력 → 파생변수 → 시계열 피처 202개
→ 위험유형 4종 추론 → 복합위험 조합 → 판단근거 추출 → 조치 결정 → 이력 기록
전부를 거친다. 아래는 그 전체를 잰 값이다.

| 항목 | 측정값 | 측정 조건 |
|---|---|---|
| 판단 1회 | **29 ms** | 1코어 고정, 단일 스레드 |
| 판단 1회 | 34 ms | 1코어, 벤치마크 스크립트 |
| 판단 1회 | 38 ms | 4코어 |
| 상주 메모리 | **181 MB** | 모델 8개 + 48시간 관측창 적재 후 |
| 최대 메모리 | 173 MB | VmHWM |
| 모델 파일 | 10.5 MB | LightGBM 텍스트 8개 |

**코어를 늘려도 빨라지지 않는다.** 1코어 34ms 와 4코어 38ms 가 사실상 같다.
이 작업은 단일 스레드에 묶여 있어서, 라즈베리파이에서는 **코어 수가 아니라
코어당 성능**만 본다.

> 위 값은 x86_64 서버급 CPU 기준이다. 라즈베리파이의 코어당 성능은 이보다
> 낮으므로 실제 제어기에서 반드시 다시 재야 한다. 다만 사업계획서 목표가
> '평균 30초 이내'이고 지금이 29ms 이므로, 코어당 성능이 수십 배 낮더라도
> 목표 안에 든다.

제어기에서 그대로 다시 재는 방법:

```bash
OMP_NUM_THREADS=1 python scripts/benchmark_inference.py \
    --cache artifacts/dataset.pkl --models artifacts/weather \
    --out artifacts/benchmark-pi
```

## 권장 사양

| 항목 | 권장 | 근거 |
|---|---|---|
| 모델 | Raspberry Pi 4 (4GB) 이상 | 상주 181MB 라 2GB 로도 돌지만, OS·수집기·웹서버가 함께 올라간다 |
| 저장장치 | **SSD (USB 부팅)** | microSD 는 로그·시계열 쓰기로 수명이 빨리 닳는다 |
| 전원 | UPS 경유 | 정전 중 쓰기가 끊기면 저장장치가 깨진다 |
| 냉각 | 방열판 + 팬 | IP65 함체 안은 여름에 온도가 오른다. 과열 시 클럭이 떨어진다 |
| OS | Raspberry Pi OS (64-bit) | LightGBM·numpy 휠이 aarch64 로 제공된다 |

사업계획서의 제어함 사양(IP65 600×500×250, 환기팬·결로방지 히터, UPS 600VA)이
이미 이 조건을 담고 있다.

## 설치

```bash
sudo apt update && sudo apt install -y python3-venv python3-dev
python3 -m venv /opt/ofdf/venv
/opt/ofdf/venv/bin/pip install -r requirements.txt

# 1코어에 묶는다. 스레드를 늘려도 빨라지지 않고 전력만 쓴다.
echo 'OMP_NUM_THREADS=1' | sudo tee /etc/default/ofdf

sudo cp deploy/ofdf-edge.service /etc/systemd/system/
sudo systemctl enable --now ofdf-edge
```

## 운영 중 확인

```bash
systemctl status ofdf-edge          # 동작 여부
journalctl -u ofdf-edge -f          # 실시간 로그
vcgencmd measure_temp               # 온도 (80℃ 넘으면 클럭 저하)
vcgencmd get_throttled              # 0x0 이 아니면 전원·발열 문제
```

## 통신이 끊겼을 때

사업계획서는 **로컬 72시간 독립운전**을 요구한다. 제어기는 서버 응답이 3분간
없으면 로컬 독립운전으로 넘어가 수집·판단·제어·기록을 계속하고, 판단 이력을
JSON Lines 로 쌓아 두었다가 복구되면 시간순으로 올린다
(`ofdf.action.journal`). 한 줄이 판단 하나라서 중간이 깨져도 나머지를 읽는다.

72시간치 판단 이력은 5분 주기 기준 864건, 한 건이 약 1.6KB 이므로 **1.4MB**
정도다. 저장공간은 문제가 되지 않는다.

## 화면

제어함의 10인치 터치패널과 농가 휴대폰이 같은 페이지를 쓴다
(`dashboard/index.html`). 기본은 **농가 화면**이고, 운영자는 상단에서 전환한다.
라즈베리파이가 로컬에서 띄우므로 인터넷이 끊겨도 현장에서 볼 수 있다.

서비스는 **셋으로 나눠** 띄운다.

| 유닛 | 하는 일 | 왜 따로인가 |
|---|---|---|
| `ofdf-edge` | 5분마다 수집·판단·조치·기록, `data.json` 갱신 | — |
| `ofdf-dashboard` | `dashboard/` 를 8080 으로 제공 | **판단이 죽어도 화면은 살아서 '멈췄다'고 알려야 한다.** 한 프로세스면 같이 죽어 농가가 아무것도 모른 채 낡은 값을 본다 |
| `ofdf-kiosk` | 터치패널에 전체화면으로 띄움 | 패널에만 필요하다. 휴대폰만 쓰는 구성에서는 안 깐다 |

```bash
sudo cp deploy/ofdf-*.service /etc/systemd/system/
sudo systemctl enable --now ofdf-edge ofdf-dashboard
sudo systemctl enable --now ofdf-kiosk      # 터치패널이 붙어 있을 때만
```

농가 휴대폰은 같은 공유기에서 `http://<파이주소>:8080/` 으로 들어온다.
**포장 내부망 전용이다.** 공인 IP 로 8080 을 열지 않는다 — 인증이 없다.

### 화면이 스스로 지키는 것

- **30초마다 다시 읽는다.** 벽패널은 아무도 새로고침하지 않는다. 1회만
  읽으면 부팅 때 값에서 영원히 멈춘다.
- **15분 넘게 갱신이 없으면 빨간 띠를 띄운다.** 판단 주기 5분 × 3회 연속
  놓침이 기준이다. 서리가 내리는 밤에 사흘 전 '정상'을 띄우는 것이 이
  화면이 할 수 있는 가장 나쁜 일이다. 연결이 끊겨도 **마지막 값을 지우지
  않고** 낡았다고 적는다 — 빈 화면보다 낫다.
- **원격 글꼴이 렌더링을 막지 않는다.** 통신이 끊긴 포장에서 글꼴 하나
  기다리느라 위험 알림이 늦으면 안 된다. 못 받으면 시스템 글꼴로 간다.
  파이에 한글을 깔아 둔다: `sudo apt install fonts-noto-cjk`
- **터치 대상 48px 이상**(휴대폰 56px). 장갑 낀 손 기준이다.

### 구동부가 덜 들어온 상태로 돌릴 때

`configs/weather.yaml` 의 `edge.installed_devices` 에 **구동부가 실제로 달린
장치만** 적는다. 여기 없는 장치로 가는 조치는 '실행'이 아니라 '권고(농가가
직접)'로 내려가고, 농가 화면에 **'직접'** 으로 표시된다.

적지 않으면 전부 달린 것으로 보고 **실행으로 기록한다.** 실증 기간의 제어
이력이 성능평가의 제어응답 측정 대상이므로, 현장에 내보내기 전에 반드시
맞춰야 하는 값이다.

```yaml
edge:
  installed_devices:
    - 관수밸브
    - 전 구동부        # 스마트 차단기로 회로 차단
    - 해당 구동부
```

구동부가 들어오면 이름을 더하면 된다. 판단 로직은 건드리지 않는다.

### 화면 꺼짐 막기

터치패널은 항상 켜져 있어야 한다. OS 세대에 따라 경로가 다르다.

```bash
# Raspberry Pi OS Bookworm 이후 (Wayland/labwc — 기본값)
sudo raspi-config nonint do_blanking 1      # 1 = 화면보호기 끔

# X11 구성일 때
xset s off -dpms
```

> 키오스크 유닛(`ofdf-kiosk.service`)과 화면 꺼짐 설정은 **실제 패널에서
> 검증하지 않았다.** 패널을 연결한 뒤 한 번 돌려보고 조정해야 한다.

## 하지 말아야 할 것

- **ONNX 변환본을 쓰지 않는다.** 추론이 70배 빨라지지만 8개 모델 중 4개가
  원본과 다른 등급을 낸다(일치율 99.7~99.9%). 네이티브 LightGBM 이 이미
  목표의 수백 배 여유를 두므로 바꿀 이유가 없다.
- **스레드 수를 늘리지 않는다.** 단일 스레드 바운드라 효과가 없고, 발열만 는다.
- **microSD 에 로그를 쌓지 않는다.** SSD 로 옮기거나 쓰기 주기를 늘린다.
